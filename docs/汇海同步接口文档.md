# 汇海数据同步接口文档

本文定义体质平台汇海同步 HTTP API，适用于任意编程语言和操作系统。接口使用 UTF-8 JSON，提供同步目标查询、学生名单读取和原始成绩上传能力。客户端的数据来源、存储方式与界面由对接方自行设计。

接口核对日期：2026-10-16。示例均为合成数据，占位域名和令牌须替换为实际接入环境的配置。

## 1. 接入、身份与目标

### 1.1 接口清单

| 方法 | 路径 | 方向与作用 | HTTP 200 含义 |
| --- | --- | --- | --- |
| GET | `/api/hh/sync/info` | 平台返回 Token 学校和当前测试项目 | 成功读取目标信息 |
| GET | `/api/hh/sync/student` | 平台分页返回学生名单 | 成功读取这一页 |
| POST | `/api/hh/sync/score` | 客户端批量上传原始成绩 | 通过边界校验后返回接收结果；全部原始明细暂存成功或已存在时 success=true，有保存失败时 success=false |

基础地址配置为 `https://<平台域名>/api/hh`，末尾不保留 `/`，拼接上述 `/sync/...` 路径。所有请求携带：

```http
Accept: application/json
Content-Type: application/json
X-Huihai-Token: <学校专属同步令牌>
```

使用 UTF-8 JSON；GET 参数放在 query string，POST 请求体为 JSON 对象。成功响应直接返回各接口指定结构，没有统一 `code` 或 `data` 包装；成绩接口单独保留 `success` ACK 字段。

`Authorization: Bearer ...` 不替代 `X-Huihai-Token`；不用学校端或小程序登录接口获取同步凭据。

### 1.2 学校专属令牌

- 平台管理员在学校“汇海同步”入口开通、重置或停用；开通／重置时完整令牌只展示一次，遗失须重置。
- 一个令牌只绑定一所学校。令牌为平台签发的不透明凭据，客户端原样保存，不自行生成或修改。格式为 `hh_<26位ULID>.<43位secret>`。
- 缺失、格式错误、不匹配、停用、重置后的旧令牌均返回 401。收到 401 停止本轮任务，不持续重试旧令牌。
- 重置或停用阻断后续请求，不构成撤销已接收队列任务的机制。
- Token、完整证件号和成绩载荷不进入版本库、普通日志或截图。排错使用合成数据并隐藏凭据。

### 1.3 学校、测试项目与学生标识

- 学校由令牌确定，测试项目由平台当前配置确定；客户端不能通过 school_id 或 project_id 选择接收目标。
- `school.id` 和 `project.id` 是平台内部主键，与客户端数据源中的标识没有数值对应关系，也不作为上传参数。
- `student_no` 是学号字符串，上传成绩时对应 `number`，须保留前导零；它不是平台学生主键。

## 2. 获取同步目标信息

```http
GET /api/hh/sync/info
```

无业务参数，成功返回：

```json
{
  "school": {"id": 10001, "name": "示例学校"},
  "project": {"id": 10008, "name": "2026 年体质测试"}
}
```

| 字段 | JSON 类型 | 含义 |
| --- | --- | --- |
| `school`、`project` | object | 两个必有对象 |
| `school.id`、`project.id` | integer | 平台内部主键 |
| `school.name`、`project.name` | string | 展示名称，不能作为关联唯一键 |

学校不存在返回 400 `{"message":"学校不存在"}`；当前项目未配置或不存在返回 400 `{"message":"当前测试项目不存在"}`。

**已知限制**：info 没有 `year/start_at/end_at` 或测试项目元数据。一次查询不锁定后续请求的目标：查询后平台切换项目，下一次 POST 使用新项目；已接收的队列任务保留接收时确定的学校／项目。年度切换应暂停同步、核对本地与远端目标，再开始新任务。客户端不能发送 project_id 固定目标。

## 3. 分页读取学生

### 3.1 请求与范围

```http
GET /api/hh/sync/student?page=1&per_page=1000
```

| 参数 | 类型 | 必填 | 默认 | 验证规则 |
| --- | --- | --- | --- | --- |
| `page` | integer | 否 | 1 | 最小 1 |
| `per_page` | integer | 否 | 1000 | 1～1000 |

query 只发送这两个字段。school_id、project_id 为禁止字段；不提供姓名、年级、修改时间或增量游标过滤。

范围为 Token 学校＋当前项目全部学生，包含免测学生；响应不提供免测标记，后台仍按免测规则拒绝其成绩。按平台学生内部 ID 升序普通分页，不按学号排序，也不按某一成绩项目资格过滤。

### 3.2 成功响应与字段

```json
{
  "items": [
    {
      "student_no": "20260001",
      "name": "示例学生",
      "id_number": "110101200801010016",
      "gender": 1,
      "grade": 31,
      "class_name": "高一 1 班"
    }
  ],
  "meta": {
    "current_page": 1,
    "per_page": 1000,
    "last_page": 1,
    "total": 421,
    "project_id": 10008,
    "project_year": 2026
  }
}
```

每条学生记录仅包含下表六个字段，所有字段均有 key。成功读取只证明身份／班级关联脏数据检查通过，不保证其余资料均已补齐。

| 字段 | JSON 类型与空值 | 语义 |
| --- | --- | --- |
| `student_no` | string，正常响应非空 | 学号；数据库最大 60 字符，但成绩 number 最大 50 |
| `name` | string | 姓名，最大 60 字符；读取接口未专项检查姓名非空 |
| `id_number` | string，正常响应非空 | 完整身份证，最大 18 字符；判重去首尾空白、忽略大小写，响应原值未必规范化 |
| `gender` | integer | 1 男，2 女 |
| `grade` | integer | 平台年级编码，见下表 |
| `class_name` | string | 关联班级名称，最大 100 字符，不是学生历史快照 |

班级关联为空或跨出当前学校／项目时返回 422；此接口未另查班级名称非空。客户端验证本地写入必要字段并报告缺失，不推导或伪造身份资料。

表中长度为平台数据库上限，不是客户端静默截断规则；本地列容量不足时报告错误，不截断身份或编码。

| 平台年级编码 | 含义 |
| --- | --- |
| 11、12、13、14、15、16 | 小学一至六年级 |
| 21、22、23 | 初中一至三年级 |
| 31、32、33 | 高中一至三年级 |
| 41、42、43、44 | 大学一至四年级 |

meta 各字段均为 integer：current_page 为请求页码，per_page 为实际每页数量，last_page 为末页，total 为范围内学生总数，project_id 为此页远端项目主键，project_year 为测试年度。

没有学生时 last_page 仍为 1；无学生或请求超出末页可以返回 200、items 空数组和完整 meta。空数组本身不是传输错误。客户端从第一页顺序读取，current_page 达到 last_page 后结束，不额外请求空页。

### 3.3 脏数据 422

每次读页前检查**整个学校／项目范围**，不是只检查本页。发现问题不返回 items/meta：

```json
{
  "message": "平台学生数据存在脏数据，请先处理后再同步",
  "data_issues": {
    "total": 1,
    "issue_counts": {"empty_school_class": 1},
    "issues": [
      {
        "reason": "empty_school_class",
        "entity": "学生",
        "id": 100001,
        "name": "示例学生",
        "code": null,
        "student_no": "20260001",
        "field": "school_class_id",
        "value": null
      }
    ]
  }
}
```

| reason | 含义 | field |
| --- | --- | --- |
| `empty_student_no` | 学号去首尾空白后为空 | student_no |
| `duplicate_student_no` | 学号去首尾空白后重复，区分大小写 | student_no |
| `empty_id_number` | 身份证去首尾空白后为空 | id_number |
| `duplicate_id_number` | 身份证去首尾空白、忽略大小写后重复 | id_number |
| `empty_school_class` | 班级关联为 null | school_class_id |
| `invalid_school_class` | 班级不存在或不在当前学校／项目 | school_class_id |

total 为问题数，同一学生可有多个问题；重复组每个学生都会贡献问题。issue_counts 是 reason → 数量对象；issues 最多 100 条样本，不能用样本长度代替 total。样本 id 为平台学生主键，code 在学生检查中为 null，value 为原字段值，可为 string、integer 或 null。客户端显示分类与数量，停止并交由平台管理员修复。

### 3.4 分页一致性

服务器使用 offset 分页，没有快照、版本号或游标。读取期间增删学生可能导致重复或遗漏，即使 total 不变也不能证明名单稳定。

建议在名单稳定时完成读取，并检查以下信息：

1. 第一页 meta.project_id 与先前查询的 info.project.id 一致。
2. 后续页的 `(project_id, project_year)` 和 `(total, per_page, last_page)` 与第一页一致。
3. 检测到目标或分页信息变化时，停止本轮读取，核对后从第一页重新开始。

上述检查不能提供快照一致性保证。学生列表中没有出现某条记录，不构成删除客户端已有数据的指令。

## 4. 上传成绩请求

```http
POST /api/hh/sync/score
```

顶层仅发送 items，一次 1～5000 条。客户端可在此范围内自行选择批量大小，无待传数据时不发送空批次。

| 字段 | JSON 类型 | 必填 | 同步验证／语义 |
| --- | --- | --- | --- |
| `items` | array of object | 是 | 非空，最多 5000 条 |
| `items[].number` | string | 是 | 非空，最大 50 字符，匹配平台学号，不是身份证 |
| `items[].code` | integer | 是 | 最小 1，存在及适用性在后台检查 |
| `items[].score` | number 或 numeric string | 是 | 原始测试值，不是评分；建议普通十进制字符串保留精度 |
| `items[].completed_at` | string | 是 | 严格 YYYY-MM-DD HH:mm:ss，秒级、Asia/Shanghai |

顶层 school_id/project_id，行内 school_id/project_id/updated_at/origin 均为禁止字段，统一不发送，非空值触发 422。只发送上表声明的字段，不透传数据源中的其它字段；服务器不承诺对未知字段逐一报错。

items[].modifier 必须不存在；空串、null 也返回422，整批不暂存、不入队。客户端须按上述白名单构造请求。平台固定保存来源 origin=1（设备／外部同步），不接受客户端指定来源。

```json
{
  "items": [
    {"number": "20260001", "code": 10001, "score": "170.5", "completed_at": "2026-09-10 10:20:30"},
    {"number": "20260001", "code": 10002, "score": "62.7", "completed_at": "2026-09-10 10:20:30"},
    {"number": "20260001", "code": 10011, "score": "3.35", "completed_at": "2026-09-10 11:00:00"}
  ]
}
```

时间不带 T、毫秒、Z 或时区偏移。源数据须转换为上海业务时间，不能把 UTC 文本直接当上海时间。日期须位于当前项目 start_at～end_at，首尾日期包含，项目缺少日期也不能保存。**格式在 HTTP 层同步验证，项目日期范围在后台异步验证**：格式正确但跨年度也可能获得成功 ACK。

重试复用原 number/code/score/completed_at，不把重试时刻当完成时间；无法解析源时间不能用当前时间代替。

## 5. 项目代码、资格与数值编码

### 5.1 代码映射

上传 code 使用以下平台项目代码，客户端须根据数据源中的项目含义进行映射。

| code | 项目 | 常规单位／编码 |
| --- | --- | --- |
| 10001 | 身高 | 厘米 cm |
| 10002 | 体重 | 千克 kg |
| 10004 | 肺活量 | 毫升 ml |
| 10005 | 50 米跑 | 秒 |
| 10006 | 立定跳远 | 厘米 cm |
| 10007 | 坐位体前屈 | 厘米 cm，可负值 |
| 10009 | 50 米×8 往返跑 | 分.秒 |
| 10010 | 800 米跑 | 分.秒 |
| 10011 | 1000 米跑 | 分.秒 |
| 10012 | 一分钟仰卧起坐 | 次 |
| 10014 | 引体向上 | 次 |
| 10018 | 一分钟跳绳 | 次 |

10024 BMI 是平台派生数据，不能作为外部成绩上传。数据源的项目编号不一定等于平台 code，不能按未经核对的编号规则推算。

表中单位解释原始值；最终范围、精度、格式以平台运行时配置的最小值、最大值、小数位数和单位为准，hh 接口不返回这些配置。不能把示例值、评分分段或本表常规单位当作生产配置查询结果。

### 5.2 年级／性别资格

| 学生范围 | 允许外部上传 code |
| --- | --- |
| 小学 11、12，男女 | 10001、10002、10004、10005、10007、10018 |
| 小学 13、14，男女 | 上述六项＋10012 |
| 小学 15、16，男女 | 上述六项＋10012、10009 |
| 初中 21～23、高中 31～33、大学 41～44，男 | 10001、10002、10004、10005、10006、10007、10011、10014 |
| 同上，女 | 10001、10002、10004、10005、10006、10007、10010、10012 |

项目还须在平台元数据中存在；此表不证明生产配置齐全。免测学生虽然下发名单，成绩仍在后台拒绝。客户端本地校验不替代后台最终检查。

### 5.3 普通数值与分秒

- 新上传全部按普通实测处理：按平台配置的小数位数使用 HalfUp 四舍五入。规范化后可写入但越界的值保存为无效成绩，不评分、选优或汇总。
- “原始”表示未经人工修改，不跳过平台规范化与校验。本接口只接收普通原始成绩，不接收人工修正命令。
- 普通数值容量为绝对值不超过 99999999.99，溢出拒绝。非数字、带单位文本、NaN、Infinity 不能保存。字符串科学计数法（如 `"1e3"`）可能通过 numeric 验证但后台拒绝；JSON number 的指数写法可能解码为普通数值，不能依赖其原始表示。客户端统一发送普通十进制形式。
- 项目单位为分.秒时使用 m.ss 编码，不是十进制分钟。小数点后前两位为秒，后续位为不足一秒并舍去；秒位必须为 00～59。

| 输入或源时长 | 含义／规范化结果 |
| --- | --- |
| `"3"` | 3 分 0 秒，编码 3.00 |
| `"3.5"`、`"3.50"` | 3 分 50 秒，不是 3 分 30 秒 |
| `"3.05"` | 3 分 5 秒 |
| `"3.359"` | 3 分 35 秒，舍去小数秒，编码 3.35 |
| `"3.60"`、`"3.6"` | 秒位 60，后台拒绝 |
| 215.9 秒真实时长 | 舍去小数秒为 215 秒，编码 3.35；不能上传 215.9 或 215.9/60 |

上传前须核对数据源的数值单位；服务器不会猜测原值是秒还是 m.ss。

## 6. ACK、异步处理与幂等

### 6.1 成功响应

```json
{"success": true, "message": "上传学生成绩成功"}
```

仅 HTTP 200＋有效 JSON 对象＋success 为 boolean true 才表示本批已接收；不只检查状态或 message。成功 ACK 表示本批全部原始明细已持久保存或已存在，客户端此时才能将本批标为已接收。入队或后续处理失败不推翻该确认。UI 表达“已接收／已上传”，不能声称正式成绩全部保存或评分完成。

当前没有批次 ID、逐条结果、进度查询、失败下载、回调或正式落库确认接口，也没有客户端请求幂等键。

### 6.2 同步与异步校验

HTTP 层检查鉴权、学校／当前项目存在及第 4 节字段结构。任一行结构错误导致整次请求 422，不保存原始记录、不入队，不能把其余行标记成功。鉴权401、目标不存在400、限流429保持原状。

原始记录先逐行独立保存，再派发异步处理。全部原始行保存成功或已存在返回 HTTP 200、success=true；任一行保存失败返回 HTTP 200、success=false，已保存行保留，客户端不得标记本批。收到 false 时提示失败并停止本轮任务；再次上传须保持原载荷。失败响应示例：

```json
{"success": false, "message": "部分原始成绩保存失败，请重新上传"}
```

后台按 number＋Token学校＋接收时 project_id 匹配平台学生，再校验资格、日期和值。不依赖客户端是否成功下发过名单：“先同步学生”是保证本地身份正确的操作流程，不是服务器完成标记。

后台可能因学生不存在、免测、项目不存在或不适用、日期越界、数值格式错误等原因拒绝正式保存。业务拒绝不等于 HTTP 422，也不撤回已返回的接收 ACK；这些逐条处理结果不通过当前接口返回。

服务端负责已接收数据的异步处理与技术故障恢复。业务拒绝或重试耗尽需由平台排查处理；客户端重复上传不重置后台处理状态。

每条汇海成绩独立事务，身高、体重是两个独立项目，不要求成对上传，也不建立成对事务。同请求其它记录不因一条坏行回滚。异步执行不保证输入行序。

### 6.3 幂等与成绩采用

原始明细按学校、接收时测试项目、学号、项目代码、原始成绩字符串和完成时间识别重复，保留首次已接收载荷。`"8.30"` 与 `"8.3"` 可作为不同原始明细接收，再由正式成绩层规范化判重。重复上传已存在的原始明细可获得成功 ACK，但不会触发已完成或已拒绝记录的重新处理。

正式成绩的判重身份为目标范围内学生＋code＋**规范化成绩**＋**秒级 completed_at**：

- 同四元组视为幂等成功；同分不同秒属于两次测试，不能仅按成绩去重。
- 非重复普通成绩新增为测试历史。计分项目按平台配置取最好成绩，身高／体重分别取最新有效值；评分、等级及加分由平台计算。
- 平台已有的人工修正成绩保留其优先级，本接口上传普通成绩不会将其覆盖为普通成绩。
- 并发上传仍存在极低概率产生重复正式记录的限制；建议同一数据源串行上传。

### 6.4 上传状态与重传

客户端自行选择上传状态的存储方式，只有收到成功 ACK 后才能将本批标为已接收。请求失败、响应异常或客户端保存上传状态失败时，保留源数据和原始载荷。

接收后 ACK 丢失，或 ACK 后客户端保存状态失败，都可能导致重传。重传须复用原 number、code、score 和 completed_at，不改变数值表示或完成时间。重复上传不能用于查询正式成绩状态，也不能自动修复后台业务拒绝。

已收到成功 ACK 的数据由服务端负责后续处理，无需周期性全量重传。若需再次上传，仍须保证载荷为未经人工修改的原始成绩。

## 7. 错误、重试与停止

| HTTP／传输结果 | 含义 | 调用方处理 |
| --- | --- | --- |
| 400 | 学校／当前项目不存在 | 停止，平台修复后重新发起 |
| 401 | Token 无效／停用／重置旧令牌 | 停止，请管理员处理 |
| 422＋errors | query 或上传字段验证失败 | 不标记，展示字段定位；修复后新请求，不循环重试 |
| 422＋data_issues | 平台学生脏数据 | 不写失败页、不继续读页；保留已提交页 |
| 429 | 限流 | 延迟重试，保留原载荷 |
| 500、502、503、504 | 服务／网关临时失败 | 有上限退避重试，保留原载荷 |
| 超时／连接中断 | 接收结果可能未知 | 不标记，原样有限重试；不推断服务器未接收 |
| 200＋success=false | 至少一条原始明细保存失败，成功行仍保留 | 不标记整批，提示错误并停止；重新启动原样补传 |
| 200 非 JSON／结构错误／success 非 true/false | 不满足接收协议 | 不标记，报告异常 |
| 404、405 或其它状态 | 路径／方法／部署等异常 | 不当成功，按接入配置排查 |

字段验证 422 示例，文本可能随部署语言变化，不逐字匹配 message：

```json
{
  "message": "The items.0.completed_at field must match the format Y-m-d H:i:s.",
  "errors": {
    "items.0.completed_at": ["The items.0.completed_at field must match the format Y-m-d H:i:s."]
  }
}
```

errors 是字段路径→字符串数组，索引从 0 开始，items.0 为本批第一条。学生非法 page/per_page 也用该结构，不能把所有 422 都当脏数据。401 示例为 `{"message":"汇海同步令牌无效"}`。

限流默认每分钟 10000 次，实际阈值由部署配置决定，不能当作每所学校独享配额。429 通常为 `{"message":"Too Many Requests."}`。**开发建议**：存在 Retry-After 时按其退避，缺失则有限指数退避；不保证消息语言固定。

客户端自行设置连接超时、读取超时、重试次数与退避间隔；接口没有要求固定的轮询周期。重试必须有上限，并保持原始载荷。

停止发送后续请求不会撤销已经接收的成绩或服务端异步任务；请求中断也不证明服务器未接收。

## 8. 对接流程与限制

1. 配置平台提供的基础地址和学校专属令牌。
2. 调用 info，核对学校及当前测试项目是否与待同步数据一致。
3. 按需分页读取学生，正确处理 null、空字符串及字符串编码；学生读取不是服务器允许上传成绩的前置完成标记。
4. 将未经人工修改的原始成绩映射为 number、code、score、completed_at，按每批 1～5000 条上传。
5. 按 HTTP 状态和 success 判断接收结果，成功 ACK 后记录上传状态；失败按第 7 节处理。

| 接口限制 | 对接要求 |
| --- | --- |
| info 不返回年度、日期范围或数值元数据 | 具体测试日期、范围、精度等由平台提供配置说明 |
| info 查询不锁定后续请求目标 | 平台切换项目时暂停同步，核对目标后恢复；不能发送 project_id 固定目标 |
| 学生读取没有快照或增量游标 | 在名单稳定时读取；变化时重新从第一页开始，见第 3.4 节 |
| 学生学号最大 60 字符，上传 number 最大 50 字符 | 超长学号需与平台核对，不静默截断 |
| 没有逐条处理结果、进度或正式落库确认接口 | ACK 只表示原始明细已接收，不推断正式保存或评分成功 |
| 上传不提供人工修正接口 | 上游保证数据原始性，人工修改后的值不能作为新原始成绩上传 |

## 9. 调用示例

使用可访问的测试环境地址、学校测试令牌、测试环境中存在的合成学生及有效项目日期。以下为通用 curl 示例；请求体采用第 4 节 JSON，保存为 UTF-8 编码的 scores.json。

```sh
curl --request GET "https://tizhi.example.invalid/api/hh/sync/info" --header "Accept: application/json" --header "X-Huihai-Token: <测试令牌>"
curl --request GET "https://tizhi.example.invalid/api/hh/sync/student?page=1&per_page=1000" --header "Accept: application/json" --header "X-Huihai-Token: <测试令牌>"
curl --request POST "https://tizhi.example.invalid/api/hh/sync/score" --header "Accept: application/json" --header "Content-Type: application/json" --header "X-Huihai-Token: <测试令牌>" --data-binary "@scores.json"
```
